# 숫자 맞히기 스펙

## 1. 기술과 파일 구성

### 기술
- Python 3.10 이상
- Flet 1.0
- Flet 문법은 강의서 3~4페이지의 main.py 뼈대에 나온 것만 사용한다. 뼈대에 없는 컨트롤, 속성, 이벤트는 쓰지 않는다.
- 표준 라이브러리만 사용한다. 정답 생성에 `random`, 테스트에 `unittest` 또는 `assert`를 쓴다. pytest 같은 외부 패키지는 쓰지 않는다.

### 파일
| 파일 | 역할 |
|---|---|
| SPEC.md | 이 문서 |
| logic.py | 정답 생성, 입력 검증, 판정, 기록 문자열 만들기. Flet을 import하지 않는다. |
| main.py | Flet 화면과 이벤트 처리. 계산과 검증은 logic.py의 함수를 호출해서 얻는다. |
| test_logic.py | logic.py의 함수만 테스트한다. 화면은 테스트하지 않는다. `python test_logic.py`로 실행할 수 있어야 한다. |

### logic.py가 제공하는 함수
| 함수 | 입력 | 출력 |
|---|---|---|
| new_answer() | 없음 | 1~100 사이 정수 하나 |
| parse_guess(text) | 입력창 문자열 | 올바르면 정수, 잘못되면 ValueError(오류 문구 포함) |
| judge(guess, answer) | 정수 두 개 | "더 큽니다", "더 작습니다", "정답입니다" 중 하나 |
| format_record(guess, verdict) | 입력값, 판정 | "50 (더 큽니다)" 형식 문자열 |
| update_best(best, tries) | 현재 최고 기록(없으면 None), 이번 시도 횟수 | 더 좋은(작은) 쪽. best가 None이면 tries (추가 기능) |

main.py는 숫자 비교, 범위 검사, 문자열 변환을 직접 하지 않는다.

## 2. 동작 규칙

1. 정답은 게임 시작 시 1~100 사이 무작위 정수 하나로 정한다. 같은 게임 중에는 바뀌지 않는다.
2. 입력은 텍스트 입력창과 "확인" 버튼으로 받는다. 제출은 "확인" 버튼으로만 한다(Enter 제출은 구현하지 않는다. 5장 참고).
3. 입력 검증(parse_guess):
   - 앞뒤 공백은 제거한다.
   - 남은 문자열이 ASCII 숫자로만 이루어져 있고 값이 1~100이면 올바른 입력이다. 앞의 0은 허용한다(예: "007"은 7).
   - 그 외(빈 칸, 문자, 소수, 부호, 1~100 밖의 숫자)는 잘못된 입력이다. 오류 문구는 "1~100 사이의 정수를 입력하세요"이다.
4. 잘못된 입력은 시도 횟수에 넣지 않고 기록 목록에도 쌓지 않는다. 입력창 아래에 오류 문구만 보여 준다. 입력창의 내용은 그대로 둔다.
5. 올바른 입력은 판정한다.
   - 입력 < 정답: "더 큽니다". 정답이 입력보다 크다는 뜻이다.
   - 입력 > 정답: "더 작습니다". 정답이 입력보다 작다는 뜻이다.
   - 입력 = 정답: "정답입니다".
6. 올바른 입력마다 시도 횟수를 1 늘리고, 기록 한 줄을 목록에 쌓고, 이번 판정을 큰 결과 문구로 보여 준다. 오류 문구는 지운다. 입력창은 비운다(자동 포커스는 하지 않는다. 5장 참고).
7. 같은 숫자를 다시 입력해도 정상 시도로 센다. 횟수 제한은 없다.
8. 정답을 맞히면 "N번 만에 맞혔습니다!"를 보여 준다. "새 게임"을 누르기 전에는 입력을 받지 않는다. 입력창과 "확인" 버튼은 화면에서 비활성화하지 않고(5장 참고), 눌러도 목록·시도 횟수·결과 문구가 바뀌지 않게 무시한다.
9. "새 게임"을 누르면 새 정답을 정하고, 목록·시도 횟수·결과 문구·오류 문구를 지우고, 입력창을 비우고 입력을 다시 받는다. 최고 기록은 지우지 않는다.

## 3. 화면 구성

창 하나, 크기 480x560, 크기 조절 불가, 밝은 테마, 배경 연한 회색(#FAFAFA), 안쪽 여백 24, 위에서 아래로 한 열로 배치한다. 창 제목은 "숫자 맞히기"이고 화면 안에 제목 글자는 따로 두지 않는다. 모든 문구는 한국어다. 배치는 강의서 과제 2의 그림을 따른다.

| 순서 | 영역 | 내용 |
|---|---|---|
| 1 | 안내 | "1부터 100 사이의 숫자를 맞힙니다." |
| 2 | 입력 줄 | 숫자 입력창(라벨 "숫자")과 파란 "확인" 버튼을 한 줄에 배치 |
| 3 | 오류 문구 | 빨간 글자. 평소에는 비어 있다. |
| 4 | 결과 문구 | 큰 굵은 글씨. 진행 중에는 마지막 판정("더 큽니다" 등), 맞힌 뒤에는 "N번 만에 맞혔습니다!" |
| 5 | 시도 횟수 | "시도 횟수: N" (시작 시 0) |
| 6 | 최고 기록 | "최고 기록: 없음" 또는 "최고 기록: N번" (추가 기능, 그림에는 없음) |
| 7 | 시도 목록 | 회색 테두리의 둥근 상자(높이 150) 안. 최신이 맨 위. 한 줄 형식은 "50 (더 큽니다)". 항목이 많으면 스크롤된다. |
| 8 | 새 게임 버튼 | 목록 아래 가로로 가득 찬 "새 게임". 항상 보이고 언제든 누를 수 있다. |

상태별 화면:
| 상태 | 입력창·확인 버튼 | 결과 문구 | 오류 문구 |
|---|---|---|---|
| 처음·새 게임 직후 | 활성 | 비어 있음 | 비어 있음 |
| 진행 중 | 활성 | 마지막 판정 | 잘못된 입력 직후에만 표시 |
| 맞힌 뒤 | 화면상 활성이지만 입력은 무시 | "N번 만에 맞혔습니다!" | 비어 있음 |

### 화면 직접 확인 (수동)
| 조작 | 기대 결과 |
|---|---|
| "abc" 입력 후 확인 | 오류 문구 표시, 시도 횟수와 목록 변화 없음 |
| 올바른 숫자 입력 | 횟수 +1, 목록 맨 위에 한 줄 추가, 입력창 비워짐 |

## 5. 추가 기능과 구현 제약

### 추가 기능: 최고 기록
- 이번 실행 중 정답을 맞힌 판의 시도 횟수 중 가장 적은 값을 "최고 기록: N번"으로 표시한다. 아직 맞힌 적이 없으면 "최고 기록: 없음"이다.
- 정답을 맞힌 순간에만 갱신하며, 비교는 `update_best(best, tries)`가 한다.
- 새 게임을 시작해도 유지한다.
- 파일에 저장하지 않는다. 프로그램을 종료하면 사라지고 다시 실행하면 "없음"으로 시작한다.

### 구현 제약 (Flet 문법이 강의서 3~4페이지 뼈대로 한정되기 때문)
| 원래 규칙 | 실제 구현 |
|---|---|
| Enter 키로 제출 | 구현하지 않음(`on_submit`이 뼈대에 없음). "확인" 버튼으로만 제출한다. |
| 맞힌 뒤 입력창·확인 버튼 비활성화 | 구현하지 않음(`disabled`가 뼈대에 없음). 화면상 활성으로 보이지만 맞힌 뒤의 입력은 무시한다. |
| 제출 후 입력창 자동 포커스 | 구현하지 않음(`focus()`가 뼈대에 없음). 입력창은 비우기만 한다. |
| 그림과 같은 색·테두리·배치 | 사용자의 요청으로 뼈대 밖 Flet 1.0 문법을 쓴다: `ft.Container`(목록 테두리·둥근 모서리), `ft.Border.all`, `ft.ButtonStyle`, `ft.RoundedRectangleBorder`(둥근 버튼), `ft.ThemeMode.LIGHT`, `page.bgcolor`, `page.padding`, `TextField`의 `expand`·`height`·`color`·`border`(`ft.OutlineInputBorder`, `ft.BorderSide`), `Button`의 `width`·`style`, 16진수 색(회색 글씨, 어두운 회색 "새 게임" 버튼, 파란 "확인" 버튼). 설치된 Flet 1.0.0에서 실행해 동작을 확인했다. |
